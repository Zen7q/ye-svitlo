# Робота з магазином «є Світло»

## Побажання власника щодо випусків

- На прохання власника закомітити й запушити зміни робіть перевірений випуск із номером версії. Оновлюйте версію пакета й lockfile, додавайте опис у CHANGELOG.md, використовуйте номер у повідомленні коміту та нову мітку `vX.Y.Z`. Надсилайте коміт і мітку до приватного GitHub-репозиторію. Не переписуйте старі мітки або історію віддаленої основної гілки.
- Перед випуском запускайте `npm test` і `npm run build`, перевіряйте змінені сценарії. Для змін, що впливають на живий магазин, використовуйте окрему гілку й перевірений preview перед просуванням у production після налаштування Vercel.
- На прохання повернути минулу версію зберігайте історію. Для живого Vercel спочатку повертайте відому робочу збірку, потім узгоджуйте код у Git окремим комітом відкату. Код не відкочує базу даних: нові замовлення, оплати та рухи складу потрібно зберегти.

## Дані й публікація

- Не комітьте і не завантажуйте до хостингової збірки `data`, паролі, локальні секрети або знімки перевірок. Справжні дані покупців і облік залишаються приватними. Перевіряйте склад підготовленого коміту перед push.
- Для перевірок замовлень, оплати та складу використовуйте ізольовані тестові дані. Не змінюйте реальні товари та замовлення заради перевірки.
- «Про магазин» і «Контакти» власник узгодить із партнерами пізніше. Не змінюйте їх без нового запиту.
- Особистий демонстраційний макет працює на Vercel з Neon і Vercel Blob. Production використовує простір даних `demo`, preview — `preview`. Локальні замовлення та пароль не мігрували. Не перетворюйте макет на реальні продажі без окремого запиту власника.
