# Особистий макет на Vercel Hobby

Ця версія призначена для особистої демонстрації, без продажів, відправлень чи оплати. У вітрині та оформленні є відповідна позначка. Для реальних продажів потрібно окремо підготувати магазин і вибрати відповідний тариф.

## Хмарні компоненти

- Vite збирає вітрину; `api/index.js` обслуговує всі API-маршрути через Vercel Function у Франкфурті.
- PostgreSQL зберігає каталог, облік, замовлення, історію, хеші паролів, сесії та ліміти запитів. Зміна замовлення і залишку відбувається в одній транзакції з блокуванням рядка. Це початкова модель даних для невеликого макета, а не схема великого магазину.
- Початкові фото з папки власника розміщені як статичні assets. Нові фото, додані через хмарну адмінку, завантажуються в окреме Blob-сховище; сервер приймає лише JPG, PNG і WebP до 3 МБ. Для цього потрібен `BLOB_READ_WRITE_TOKEN`.
- Секрети задаються в серверних environment variables Vercel. Вони не потрапляють у фронтенд. API не повертає закупівельних сум, замовлень і даних постачальників публічному користувачу.

## Початкові демонстраційні дані

17 моделей Deye, 56 фото в галереях та постачальник NKON взяті з матеріалів власника. Однакові файли фото зберігаються один раз. Ціна постачальника — приблизна гривнева сума з ПДВ із наданого опису. Ціна продажу дорівнює цій сумі плюс 15%, із точністю до копійки. Ці числа не перевірялися як актуальні ринкові чи закупівельні ціни.

Нова хмарна база отримує по 3 **тестові** одиниці кожного товару, із записом про демонстраційний залишок у журналі. Фактичної поставки немає. Реальні локальні замовлення, паролі, складська історія та закупівлі не переносяться. Початкове наповнення виконується лише за відсутності рядка відповідного простору даних: нова збірка не стирає редагування або тестові замовлення.

## Налаштування власником

Потрібні `DEMO_MODE=true`, `DATABASE_URL`, `YE_STORE_NAMESPACE=demo`, приватний випадковий `ADMIN_SETUP_TOKEN` довжиною щонайменше 32 символи та токен Blob. Адмінка відкривається через `/admin`. Перший доступ створюється лише з приватним кодом власника, а не довільним відвідувачем. Після створення доступу логін і пароль зберігаються як логін та scrypt-хеш у базі; можна прибрати код початкового налаштування з environment variables після успішного входу.

Для іншого середовища використовуйте окрему базу або окремий `YE_STORE_NAMESPACE`. Не підключайте неперевірену preview-збірку до майбутньої бази реальних замовлень. Відкат збірки не відкочує PostgreSQL.

## Перевірки

`npm test` перевіряє також SQL-запити на ізольованому PostgreSQL у PGlite: відкат транзакції, конфлікти редагування, повтори оформлення, приватність, сесії між екземплярами, ліміти та збереження редагувань після повторної ініціалізації. Це локальна перевірка; підключення до Neon та реальний сценарій на Vercel перевіряються окремо після налаштування ресурсів.
