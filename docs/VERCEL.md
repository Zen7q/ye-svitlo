# GitHub → Vercel для «є Світло»

Код можна зберігати у приватному GitHub-репозиторії та підключити його до Vercel. Vercel створює preview для змін у гілках і production-версію після оновлення обраної основної гілки. Доступ до репозиторію дозволяє продовжувати редагування коду з цього робочого простору. Власником GitHub і Vercel залишається власник магазину; постійний окремий доступ для агента не створюється.

[Офіційна інтеграція GitHub](https://vercel.com/docs/git/vercel-for-github)

## Домен

Vercel надає адресу з закінченням `.vercel.app`. Пізніше до того самого проєкту можна додати власний домен у Settings → Domains та налаштувати DNS у реєстратора. Купувати домен саме у Vercel не обов’язково.

[Налаштування домену](https://vercel.com/docs/domains/working-with-domains/add-a-domain)

## Що потрібно перенести перед публікацією магазину

Зараз API існує у Vite-плагіні `configureServer` і працює лише з локальним сервером розробки. Збірка `dist` містить вітрину, але не API для каталогу, входу, оформлення, промокодів чи Нової пошти. Завантаження самої цієї збірки на Vercel не дасть працездатного магазину.

Потрібні серверні маршрути для Vercel, постійна база даних для товарів і замовлень, сховище фото та сесії адміністратора, що працюють між серверними інстансами. Локальні черги записів і ліміти запитів також потрібно замінити спільними механізмами. Перші облікові дані потрібно налаштовувати приватно: локальна початкова форма зараз дозволяє налаштування лише через localhost.

Фото зараз вбудовані у JSON. Файли `data/store.json`, `data/auth.json` та історія містять приватні облікові дані й контакти: їх не можна використовувати як публічні assets або завантажувати до GitHub. `.gitignore` і `.vercelignore` виключають дані, локальні секрети й знімки перевірок. Міграція даних має виконуватися окремо, із збереженням приватних і публічних полів та перевіркою залишків, оплат і цін.

[Зберігання файлів у Vercel Functions](https://vercel.com/kb/guide/how-can-i-use-files-in-serverless-functions)

Безкоштовна адреса не означає безкоштовний тариф для магазину: Hobby дозволяє особисте некомерційне використання. Для комерційного магазину потрібен відповідний тариф.

[Умови Hobby](https://vercel.com/docs/plans/hobby)

## Випуски й повернення

Репозиторій має бути приватним. Випуски позначаються мітками `vX.Y.Z`, а коміт і CHANGELOG містять номер та опис змін. Для перевірки змін перед живим магазином використовуйте гілку, pull request і preview, після перевірки — просування в production.

Мітка Git дозволяє повернути код, але повторне складання займає час. Для швидкого відновлення живого сайту Vercel має Instant Rollback до вже готової production-збірки. Після цього потрібно узгодити основну гілку окремим комітом відкату. Нові замовлення й записи бази не повертаються автоматично разом із кодом. Сумісність серверного коду зі схемою даних перевіряється окремо.

[Офіційний Instant Rollback](https://vercel.com/docs/instant-rollback)

Vercel-проєкт ще не підключений. Цей файл фіксує перевірений спосіб публікації та обмеження поточної реалізації.
