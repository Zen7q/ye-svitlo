# GitHub → Vercel для «є Світло»

Код можна зберігати у приватному GitHub-репозиторії та підключити його до Vercel. Vercel створює preview для змін у гілках і production-версію після оновлення обраної основної гілки. Доступ до репозиторію дозволяє продовжувати редагування коду з цього робочого простору. Власником GitHub і Vercel залишається власник магазину; постійний окремий доступ для агента не створюється.

[Офіційна інтеграція GitHub](https://vercel.com/docs/git/vercel-for-github)

## Домен

Vercel надає адресу з закінченням `.vercel.app`. Пізніше до того самого проєкту можна додати власний домен у Settings → Domains та налаштувати DNS у реєстратора. Купувати домен саме у Vercel не обов’язково.

[Налаштування домену](https://vercel.com/docs/domains/working-with-domains/add-a-domain)

## Хмарний демонстраційний макет

[Відкрити макет](https://ye-svitlo-theta.vercel.app) · [Адмінка](https://ye-svitlo-theta.vercel.app/admin)

Проєкт `ye-svitlo` підключений до приватного репозиторію `Zen7q/ye-svitlo`. Для особистого некомерційного показу власник обрав Hobby. Макет явно позначено як демонстраційний: оформлення створює тестові замовлення, реальні продажі та оплата не проводяться. Перед реальними продажами потрібні відповідний комерційний тариф і окреме налаштування робочого обліку.

Серверні маршрути знаходяться в `api/index.js`. Дані каталогу, тестових замовлень, собівартості та складу зберігаються у Neon PostgreSQL; сесії та ліміти запитів також спільні між інстансами. Транзакції блокують одночасний продаж останньої одиниці та повторне зарахування поставки. Preview використовує окремий простір даних `preview`, production — `demo`. Початковий каталог містить 17 моделей Deye й 56 посилань на фотографії; умовні залишки — по 3 одиниці для перевірки. Початкові фотографії включені у публічні assets, нові фото завантажуються в Vercel Blob.

Локальні замовлення, пароль і складська історія не перенесені. Локальний сайт залишається окремим від хмарного демонстраційного обліку. Розділи «Про магазин» й «Контакти» не змінено.

Перший вхід у хмарну адмінку потребує приватного коду власника з локального `.vercel/bootstrap-token`. Власник сам обирає логін і пароль. Код передається серверу тільки під час початкового налаштування; його не можна публікувати або передавати у URL. Вхід надалі перевіряє логін та пароль, а закупівельні дані не входять у публічний API. Секрети зберігаються у Vercel Environment Variables, ніколи з префіксом `VITE_`.

Файли `data/store.json`, `data/auth.json`, приватні коди, env-файли й історія виключені з Git та хостингової збірки. Дивіться також [архітектуру макета](CLOUD-DEMO.md).

[Умови Hobby](https://vercel.com/docs/plans/hobby)

## Випуски й повернення

Репозиторій має бути приватним. Випуски позначаються мітками `vX.Y.Z`, а коміт і CHANGELOG містять номер та опис змін. Для перевірки змін перед живим магазином використовуйте гілку, pull request і preview, після перевірки — просування в production.

Мітка Git дозволяє повернути код, але повторне складання займає час. Для швидкого відновлення живого сайту Vercel має Instant Rollback до вже готової production-збірки. Після цього потрібно узгодити основну гілку окремим комітом відкату. Нові замовлення й записи бази не повертаються автоматично разом із кодом. Сумісність серверного коду зі схемою даних перевіряється окремо.

[Офіційний Instant Rollback](https://vercel.com/docs/instant-rollback)

Vercel-проєкт підключений. Зміни в основній гілці запускають нову production-збірку; перед ними потрібно перевіряти preview.
